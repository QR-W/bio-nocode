# Bio Zero Code / 生物实验零代码平台 — 项目说明

> 基于当前仓库代码整理，可用于对外介绍、答辩材料或内部文档。产品界面中首页品牌为「BioForm」，认证页为「BioZeroCodeForm」，下文统一以**本平台**指代。

---

## 1. 产品定位

面向**细胞生物学实验**场景的**零代码 Web 应用**：用户通过**自然语言描述**或选择**实验类型模板**，由 **LLM** 生成**结构化应用配置**（字段、多页面布局、图表与表格视图等），在浏览器内**预览、对话迭代、保存为应用**，在运行态完成**数据录入、列表、图表分析与导出**。

**本地优先**：应用配置、业务数据、平台用户主要存储在浏览器 **IndexedDB**（Dexie）；调用 LLM 所需 **API Key** 由用户在设置页填写，说明为仅保存在本地、不上传自有服务器（实现上 Key 仍由浏览器直连接口提供方，需注意安全习惯）。

## 2. 技术栈

| 类别 | 选型 |
|------|------|
| 框架 | React 19、TypeScript |
| 构建 | Vite 8 |
| UI | Ant Design 6、中文 locale、主题主色 `#4F46E5` |
| 路由 | React Router 7（`createBrowserRouter`、路由级懒加载） |
| 状态 | Zustand（部分 `persist` 至 localStorage） |
| 本地数据库 | Dexie 4，库名 `NoCodePlatformDB`，当前 schema **version 2** |
| 图表 | Recharts |
| LLM | OpenAI 兼容客户端；当前实现固定请求 **DeepSeek**（见第 7.4 节） |
| 导出 | JSZip（打包可运行 React 项目 ZIP）；运行页支持 CSV |
| 其他 | `@dnd-kit/*`（构建器相关交互） |

**部署**：根目录 `vercel.json` 将路径重写至 `index.html`，支持 SPA 托管。

## 3. 架构分层

1. **页面**（`src/pages/`）：首页、认证、应用构建器、应用运行器、设置。  
2. **组件**  
   - `components/builder/`：实验类型选择、对话面板等  
   - `components/editor/`：属性面板、`useEditorStore`  
   - `components/runner/`：构建器右侧预览等  
   - `components/engine/PageRenderer.tsx`：按页面配置将组件类型映射到 Widget  
   - `components/widgets/`：表单、表格、图表、登录、搜索栏等  
3. **领域类型**（`src/types/AppConfig.ts`）：全项目配置与数据契约。  
4. **数据访问**（`src/services/db/`）：`db.ts`、`appRepo`、`recordRepo`、`userRepo`。  
5. **LLM**（`src/services/llm/`）：提示词、`appGenerator`、`llmClient`。  
6. **路由与守卫**：`src/router/index.tsx`、`AuthGuard.tsx`。

## 4. 路由说明

| 路径 | 说明 |
|------|------|
| `/auth` | 登录 / 注册（公开） |
| `/` | 工作台首页（需登录） |
| `/builder` | 新建应用 |
| `/builder/:appId` | 迭代已有应用 |
| `/app/:appId` | 运行应用（录入数据、图表等） |
| `/settings` | DeepSeek API Key 与可选 API 根地址 |
| `*` | 重定向到 `/` |

未登录访问受保护路由时，`AuthGuard` 重定向至 `/auth`。

## 5. 核心数据模型（`AppConfig`）

### 5.1 实验类型 `ExperimentType`

六种：`passage`（传代）、`cryopreservation`（冻存与复苏）、`transfection`（转染）、`flow_cytometry`（流式）、`drug_assay`（药效检测）、`project`（课题管理）。在 `prompts.ts` 中按类型注入领域知识。

### 5.2 组件类型 `ComponentType`

例如：`DataForm`、`DataTable`、`StatsCards`、`ChartView`、`LoginForm`、`SearchBar`、`RichTextEditor`、`FileUploader`、`Timeline` 等。需与 `PageRenderer` 内注册表一致；未支持类型在运行页会有占位提示。

### 5.3 字段 `FieldDef`

类型包括 `text`、`textarea`、`number`、`date`、`select`、`multiselect`、`boolean`、`file`；可校验、单位、选项、帮助文案、输入样式等。

### 5.4 页面 `PageConfig`

`key`、`title`、`icon`（字符串，运行器映射到 Ant Design Icons）、`components` 有序列表、可选页面样式。

### 5.5 视图 `ViewConfig`

`tableColumns`、`defaultSort`、`charts`（折线/柱/散点/饼，字段绑定 `FieldDef.name`）。

### 5.6 `AppConfig`

`id`、`name`、`description`、`experimentType`、`cellLine`、`fields`、**`password`（应用访问密码，非平台账号）**、`views`、`pages`、`version`、`userId`、时间戳等。

### 5.7 `DataRecord`

`appId` + `data: Record<string, unknown>` + 时间戳。

### 5.8 `PartialAppConfig`

供 LLM 增量更新；不含由系统维护的 `id`、`userId`、`createdAt`、`updatedAt`、`version` 等字段的强制完整形态。

## 6. 本地存储（Dexie）

### 6.1 表与索引

- `apps`：`id, updatedAt, userId`  
- `records`：`id, appId, createdAt`  
- `users`：`id, username`  

### 6.2 `appRepo`

- **创建**：合并部分配置；若缺少 `pages` 则写入默认多页（含登录、概览、录入、列表、图表等）。  
- **列表**：仅当前登录用户的 `userId`。  
- **更新**：`version` 自增，更新 `updatedAt`。  
- **删除**：事务内删除应用及其全部 `records`。  
- **统计**：`countRecords` 供首页展示记录条数。

### 6.3 `recordRepo`

创建、按应用列举、更新、删除、按字段名导出 **CSV**。

### 6.4 平台用户 `userRepo`

注册校验用户名唯一；登录校验密码。**注意**：当前密码存储为 `btoa(encodeURIComponent(password))`，属演示级，非安全哈希。

### 6.5 认证状态 `authStore`

Zustand `persist`（`nocode-auth`），刷新后仍可保持平台登录态。

## 7. LLM 生成与迭代

### 7.1 流程

- **首次**：`generateApp(用户输入, experimentType)`。  
- **迭代**：`updateApp(用户输入, currentConfig)`。

### 7.2 返回处理

从模型输出中提取 JSON（支持剥离 markdown 代码块）；`JSON.parse` + 基础校验（如 `name` 为字符串、`fields` 为数组）；失败则向用户展示错误信息。

### 7.3 与构建器联动

- 合并新生成配置与当前配置；新建时尚无完整实体则补时间与版本等占位字段。  
- 新建首次生成会清理 LLM 可能带来的 `password`，并引导用户在对话中设置**应用访问密码**（若配置含登录页则保存前必检）。  
- 保存：`appRepo.create` 或 `appRepo.update`，成功后进入 `/app/:id`。

### 7.4 `llmClient` 实现要点（务必对外表述一致）

- **仅支持 DeepSeek**：模型固定为 `deepseek-chat`（与设置页文案一致）。  
- **API 根地址**：默认 `https://api.deepseek.com`；若在设置中填写「API 根地址」，则优先使用该值（适用于自建兼容代理）。  
- API Key 来自设置 Store；使用浏览器直连：`dangerouslyAllowBrowser: true`，需提示用户保护 Key、注意公共设备与厂商政策。

## 8. 应用构建器（`AppBuilderPage`）

- 可先选实验类型，或通过 URL 参数 + `sessionStorage` 带入首页生成的首条自然语言需求。  
- 布局：左侧对话或属性面板（选中元素时），右侧实时预览。  
- 离开页面时重置 `builderStore` 与编辑器选中态，避免污染下次新建。

---

## 9. 应用运行器（`AppRunnerPage`）

- 加载应用配置与记录列表。  
- **应用内登录**：若存在 `LoginForm` 且配置了 `app.password`，需校验密码；会话用 `sessionStorage`（如 `loggedIn_${appId}`、`username_${appId}`）。无登录页或无密码时可直接使用。  
- 侧栏菜单一般**不展示登录页**；未登录切换菜单时可能提示先登录。  
- 通过 `PageRenderer` 渲染当前页，并注入提交、删除、导出、登录回调等。  
- 若历史数据无 `pages` 字段，使用代码内与默认结构等价的 fallback 页面。  
- 支持 **CSV 导出**与**导出 React 源码 ZIP**（`exportReactProject`）。

---

## 10. 设置页（`SettingsPage`）

配置 **DeepSeek API Key**、可选 **API 根地址**；界面明确说明当前仅 DeepSeek，Key 仅保存在浏览器本地。

## 11. 安全与合规提示（对外说明建议保留）

- 无自有后端时，数据与逻辑均在用户浏览器侧；**应用访问密码**与平台密码**不应**视为高安全方案。  
- 平台密码当前非密码学安全存储。  
- LLM Key 走用户浏览器至第三方 API，需合规与隐私告知。
